# 提示词设计最佳实践 - 避免重复

## 问题

用户提出：为什么要在 system prompt 和 memory prompt 中同时加入提示词？

这是一个很好的观察！确实存在重复和冗余的问题。

## 原始设计的问题

之前有**三处**记忆相关的提示词：

1. **系统提示词** (`L1_system_prompt.py`)
   - 包含详细的记忆使用指南
   - 列出了5种需要记忆的场景
   - 说明了如何使用分类和优先级

2. **工具提示词** (`memory_prompt.py`)
   - 同样详细的使用说明
   - 相同的场景和示例
   - 基本重复了系统提示词的内容

3. **工具描述** (`memory.py` 中的 description)
   - 简短的描述

### 造成的问题

- ❌ **信息重复**: 相同内容出现在多个地方
- ❌ **上下文浪费**: 重复内容占用宝贵的 token
- ❌ **维护困难**: 需要同步更新多处,容易不一致
- ❌ **潜在冲突**: 如果不同地方说法不同,会混淆 Agent

## 优化后的设计

### 职责分离原则

```
系统提示词 (L1_system_prompt.py)
├── 角色: 定义 Agent 的整体行为原则
├── 内容: 高层次指导,简洁明确
└── 示例: "主动使用 memory 工具记忆用户信息"

工具提示词 (memory_prompt.py)
├── 角色: 详细说明工具的使用方法
├── 内容: 完整的使用指南、示例、最佳实践
└── 示例: 详细的分类说明、优先级使用、场景示例

工具描述 (memory.py description)
├── 角色: 工具的基本介绍
├── 内容: 简短描述工具的功能
└── 示例: "管理长期记忆,保存和检索用户信息"
```

### 具体实现

#### 1. 系统提示词 - 简洁原则

```python
## Persistent Memory
You have access to a persistent memory system via the 'memory' tool for storing user-specific information across all sessions.

**IMPORTANT: Proactively use the memory tool when users share personal information, preferences, or context.** 
See the memory tool description for detailed usage guidelines.
```

**特点**:
- ✅ 简洁明了,只说明核心原则
- ✅ 指向详细文档(工具提示词)
- ✅ 不重复具体细节

#### 2. 工具提示词 - 详细完整

```python
## Memory Tool - Persistent Memory Management

### 🎯 AUTOMATIC TRIGGERS - When to Use
**You MUST proactively call this tool WITHOUT asking for permission when:**
1. User Introduces Themselves
2. User States Preferences
3. User Describes Current Work
...

### 📝 How to Use
[详细的使用说明]

### ✅ Best Practices
[最佳实践]

### 📚 Detailed Examples
[具体示例]
```

**特点**:
- ✅ 包含所有必要的详细信息
- ✅ 提供丰富的示例和最佳实践
- ✅ 结构清晰,易于理解

#### 3. 工具描述 - 简要介绍

```python
description="管理长期记忆,用于保存和检索重要信息、用户偏好等。记忆会在所有会话中持久保存。"
```

**特点**:
- ✅ 简短描述功能
- ✅ 不包含使用细节

## 设计原则

### 1. 单一职责原则

每个提示词文件有明确的职责:

- **系统提示词**: 定义 Agent 的整体行为和职责
- **工具提示词**: 说明特定工具的使用方法
- **工具描述**: 提供工具的基本介绍

### 2. 避免重复原则

信息只在一个地方维护:

- 使用场景 → 工具提示词
- 技术细节 → 工具提示词
- 行为指导 → 系统提示词(高层次) + 工具提示词(详细)

### 3. 层次化原则

```
层次 1: 系统提示词 (What & Why)
  └── "你要主动记忆用户信息"

层次 2: 工具提示词 (How & When)
  └── "在以下5种情况下使用,使用方法如下..."

层次 3: 工具描述 (Quick Ref)
  └── "管理长期记忆的工具"
```

### 4. 可维护性原则

- 信息集中在最合适的位置
- 修改时只需更新一处
- 避免信息不一致

## Token 使用对比

### 优化前

```
系统提示词: ~500 tokens (包含详细使用说明)
工具提示词: ~600 tokens (重复相同内容)
总计: ~1100 tokens (重复约500 tokens)
```

### 优化后

```
系统提示词: ~50 tokens (仅核心原则)
工具提示词: ~800 tokens (完整详细信息)
总计: ~850 tokens
节省: ~250 tokens (约22%)
```

## 类比说明

这就像编写技术文档:

```
README.md (系统提示词)
└── "使用 memory 工具来记住用户信息,详见工具文档"

docs/memory-tool.md (工具提示词)
└── "详细的API文档、使用示例、最佳实践..."

代码注释 (工具描述)
└── "简短的功能说明"
```

## 实施效果

### ✅ 优点

1. **上下文更高效**: 减少重复内容,节省 token
2. **维护更简单**: 只需在一个地方更新详细信息
3. **结构更清晰**: 职责分离,层次分明
4. **扩展更容易**: 添加新工具时遵循相同模式

### ❌ 避免的做法

1. 在系统提示词中重复工具的详细使用说明
2. 在多个地方维护相同的信息
3. 系统提示词过于详细,工具提示词过于简单

## 其他工具的参考

这个模式适用于所有工具:

```python
# 系统提示词
## Search Tools
Use search tools (grep, glob) to explore codebases efficiently.

# 工具提示词 (grep_prompt.py)
## Grep Tool - Code Search
### When to Use
### How to Use
### Examples
### Best Practices
...

# 工具描述
description="Search file contents using regular expressions"
```

## 总结

**正确的提示词设计**:
- ✅ 系统提示词: 高层次原则,简洁指导
- ✅ 工具提示词: 详细说明,完整示例
- ✅ 工具描述: 简短介绍

**避免重复**:
- 信息只在最合适的地方出现一次
- 不同层次提供不同粒度的信息
- 维护时只需更新一个地方

这样可以:
- 🎯 提高上下文效率
- 🔧 简化维护工作
- 📚 提供清晰的层次结构
- 🚀 支持未来扩展
